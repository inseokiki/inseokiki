# 세션 종료 루틴

phy_lab(회사) 쪽 session-end 스킬의 구조를 이식하되, Notion 연동(Dev Notes/데일리 노트)
단계는 이 프로젝트엔 없으므로 제외했다 — 로컬 파일 갱신 + lab 백업 동기화만 처리한다.

## 0. 사전 — 오늘 작업 내용 추출 (사용자에게 묻지 않음)

현재 대화 컨텍스트에서 다음을 정리한다:
- 오늘 다룬 작업 항목들 (제목 + 핵심 내용, 완료/진행중/보류 구분)
- 사용자가 명확히 교정하거나("아니 그게 아니라...") 확인해준("맞아, 그렇게 해") 비자명한 판단 —
  있으면 교훈 후보, 없으면 이번엔 lessons.md 갱신 생략
- 후속으로 남은 과제 (다음 세션에서 이어갈 것)

이 요약 하나를 아래 단계에 형태만 바꿔 재사용한다 — 매번 다시 추출하지 않는다.

## 1. lessons.md 갱신

- 대상: `tasks/lessons.md`
- 0단계에서 교훈 후보가 있을 때만 추가. 없으면 이 단계는 건너뛰고 반환 시 "교훈 없음 — 생략"이라고 밝힌다.
- 형식 (기존 파일 "교훈 목록" 아래, 최신이 위로 오도록 삽입):
  ```
  ### YYYY-MM-DD — 짧은 제목
  **무엇**: 어떤 실수/교정이 있었는지, 또는 어떤 접근이 맞다고 확인됐는지
  **왜**: 사용자가 왜 그렇게 지적/확인했는지 (근거, 과거 사고 이력 등)
  **적용**: 앞으로 언제/어떻게 이 교훈을 적용할지
  ```

## 2. todo.md 갱신

- 대상: `tasks/todo.md`
- "진행 중" 섹션에 있던 항목 중 오늘 완료된 것은 체크 표시하고 "완료" 섹션으로 이동 —
  이동 시 `### YYYY-MM-DD — 제목` 헤더 + `- [x]` 체크리스트 + 짧은 **검토** 문단 형식을 따른다
  (기존 파일의 다른 완료 항목들과 동일한 톤).
- 새로 생긴 후속 과제는 "다음 후보" 섹션의 적절한 그룹(A/B/C)에 `- [ ]`로 추가.
- 오늘 아무 것도 완료되지 않았으면 "진행 중"만 최신 상태로 갱신하고 "완료" 섹션은 건드리지 않는다.
- 완료된 기능의 상세 구현/실측 결과는 여기 남기지 않고 `docs/analysis/history.md`에 기록한다
  (기존 파일 상단 안내 참조).

## 3. lab 백업 동기화

`lab/scripts/backup_sync.py` 호출. Claude가 파일을 직접 복사하지 않고 반드시 이 스크립트를
통해서만 진행한다. 이 프로젝트는 맥미니와 Windows(WSL2) 두 머신에서 개발하므로, 실행 중인
머신에 맞는 스크립트 경로와 `--project` 키를 골라야 한다 (`lab/scripts/backup_manifest.yaml`
참조 — 머신별로 project 키가 분리되어 있음):

- **맥미니**: `python3 /Users/kang/Desktop/study/scripts/backup_sync.py --project inseokiki-macmini --apply`
- **Windows(WSL2)**: `python3 /home/inseok/study/5g/lab/scripts/backup_sync.py --project inseokiki-windows --apply`

어느 머신인지 애매하면 실행 전 `hostname`/`pwd`로 먼저 확인한다.

- `--apply`를 바로 써도 안전함 — 스크립트 자체가 신규/원본만-변경(COPY) 파일만 실제
  복사하고, `CONFLICT`(백업만 변경됨/양쪽 변경됨/이력 없이 내용 다름)나
  `DELETE-CANDIDATE`(원본에서 삭제됨)는 **절대 자동으로 덮어쓰거나 지우지 않음** — 리포트만
  하고 넘어간다.
- 실행 결과(stdout)의 `요약:` 줄을 그대로 파싱해 반환 형식 3번째 줄에 반영한다.
- `conflict` 또는 `delete_candidate`가 1건 이상이면, 해당 파일 경로와 이유를 사용자에게
  같이 보여준다(수동 확인 필요 — 세션 종료를 막지는 않음).
- 스크립트 실행 자체가 실패(예: PyYAML 없음, manifest 못 찾음)하면 "⚠️ lab 백업 실패:
  <이유>"로 보고하고, 이 단계 실패가 1~2단계(lessons/todo) 완료 여부에 영향을 주지 않는다 —
  각 단계는 서로 독립적으로 성공/실패를 보고한다.

## 반환 형식

3개 항목 각각 처리 결과를 체크리스트로 요약:
```
✅/⏭️ lessons.md: 교훈 1건 추가 / 교훈 없음 — 생략
✅ todo.md: 완료 N건 이동, 신규 후속 M건 추가
✅/⚠️ lab 백업: 변경 N개, 동일 N개, 제외 N개, 충돌 N개
```

## 공통 규칙

- 날짜는 항상 KST(UTC+9) 기준.
- 3개 단계는 서로 독립적이므로 순서 상관없이 처리 가능하지만, 위 순서(lessons → todo → lab 백업)를
  기본으로 따른다.
- 실제로 일어난 일만 기록한다 — 애매하거나 확인 안 된 내용을 추측해서 채우지 않는다.
