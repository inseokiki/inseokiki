phy_lab(회사) 쪽 session-end 스킬의 구조를 이식했다. 2026-08-30부터 Notion 연동도
회사 워크스페이스와 같은 계정(같은 Notion MCP 연결)을 그대로 쓰되, 페이지는 분리했다 —
회사 FlexRAN Dev Notes/데일리 노트에 개인 스터디 내용을 섞지 않기 위함(단, 데일리 노트는

## 0. 사전 — 오늘 작업 내용 추출 (사용자에게 묻지 않음)

현재 대화 컨텍스트에서 다음을 정리한다:
- 오늘 다룬 작업 항목들 (제목 + 핵심 내용, 완료/진행중/보류 구분)
- 사용자가 명확히 교정하거나("아니 그게 아니라...") 확인해준("맞아, 그렇게 해") 비자명한 판단 —
  있으면 교훈 후보, 없으면 이번엔 lessons.md 갱신 생략
- 후속으로 남은 과제 (다음 세션에서 이어갈 것)

이 요약 하나를 아래 단계에 형태만 바꿔 재사용한다 — 매번 다시 추출하지 않는다.

## 1. Dev Notes 업로드

- `notion-update-page`, command: `insert_content`, position: `{"type": "end"}`
- page_id: `3cce6bb00fd78128bb7ad4106c8921f4` (🔬 Dev Notes - 개인 스터디, 회사 FlexRAN
  Dev Notes와 별도, 2026-08-30 신설)
- 토글 형식 (FlexRAN Dev Notes와 동일 컨벤션, 날짜 제목 필수):
  ```
  <details>
  <summary>\[YYYY-MM-DD\] 제목</summary>
  	**작업 내용**
  	- ...
  	**확인 사항** (있으면)
  	- ...
  	**다음 할 일** (있으면)
  	- ...
  </details>
  ```
  버그 조사/디버깅류 작업이면 **증상/근거/기각 가설/원인/조치** 구조를 대신 써도 된다.
- `[`, `]`는 반드시 `\[`, `\]`로 이스케이프한다 (Notion 마크다운 규칙).
- 페이지 안에 월별로 묶인 토글(`📁 YYYY-MM`)이 이미 있으면 해당 월 토글 안에 최신이 위로
  오도록 넣는다 — 아직 이번 달 토글이 없으면 새로 만든다.

## 2. lessons.md 갱신

- 대상: `tasks/lessons.md`
- 0단계에서 교훈 후보가 있을 때만 추가. 없으면 이 단계는 건너뛰고 반환 시 "교훈 없음 — 생략"이라고 밝힌다.
- 형식 (기존 파일 "교훈 목록" 아래, 최신이 위로 오도록 삽입):
  ```
  ### YYYY-MM-DD — 짧은 제목
  **무엇**: 어떤 실수/교정이 있었는지, 또는 어떤 접근이 맞다고 확인됐는지
  **왜**: 사용자가 왜 그렇게 지적/확인했는지 (근거, 과거 사고 이력 등)
  **적용**: 앞으로 언제/어떻게 이 교훈을 적용할지
  ```

## 3. todo.md 갱신

- 대상: `tasks/todo.md`
- "진행 중" 섹션에 있던 항목 중 오늘 완료된 것은 체크 표시하고 "완료" 섹션으로 이동 —
  이동 시 `### YYYY-MM-DD — 제목` 헤더 + `- [x]` 체크리스트 + 짧은 **검토** 문단 형식을 따른다
  (기존 파일의 다른 완료 항목들과 동일한 톤).
- 새로 생긴 후속 과제는 "다음 후보" 섹션의 적절한 그룹(A/B/C)에 `- [ ]`로 추가.
- 오늘 아무 것도 완료되지 않았으면 "진행 중"만 최신 상태로 갱신하고 "완료" 섹션은 건드리지 않는다.
- 완료된 기능의 상세 구현/실측 결과는 여기 남기지 않고 `docs/analysis/history.md`에 기록한다
  (기존 파일 상단 안내 참조).

  하루 1개라 원래부터 FlexRAN 쪽에서도 같은 DB를 쓴다, 분리하지 않음)

- 오늘 페이지가 없으면 먼저 생성(속성: 날짜=오늘, 작성 완료=`__NO__`, 내용 템플릿
  `## ✅ 오늘 할 일` / `## 📝 오늘 한 일` / `## 🔄 내일 할 일`).
- 있으면 `notion-update-page` (`update_content`)로 `## 📝 오늘 한 일` 섹션에 0단계 요약을
  추가한다 — 이미 그날 다른 작업(FlexRAN 등) 내용이 적혀 있으면 그건 지우지 않고 이어서
  덧붙인다(같은 날 여러 프로젝트를 다뤘을 수 있음). 기존 "오늘 할 일" 목록도 건드리지 않음.
- 남은 후속 과제가 있으면 `## 🔄 내일 할 일` 섹션에 반영한다(기존 내용에 이어서 추가).

## 5. lab 백업 동기화

`lab/scripts/backup_sync.py` 호출. Claude가 파일을 직접 복사하지 않고 반드시 이 스크립트를
통해서만 진행한다. 이 프로젝트는 맥미니와 Windows(WSL2) 두 머신에서 개발하므로, 실행 중인
머신에 맞는 스크립트 경로와 `--project` 키를 골라야 한다 (`lab/scripts/backup_manifest.yaml`
참조 — 머신별로 project 키가 분리되어 있음):

- **맥미니**: `python3 /Users/kang/Desktop/study/5g/lab/scripts/backup_sync.py --project inseokiki-macmini --apply`
- **Windows(WSL2)**: `python3 /home/inseok/study/5g/lab/scripts/backup_sync.py --project inseokiki-windows --apply`

어느 머신인지 애매하면 실행 전 `hostname`/`pwd`로 먼저 확인한다.

- `--apply`를 바로 써도 안전함 — 스크립트 자체가 신규/원본만-변경(COPY) 파일만 실제
  복사하고, `CONFLICT`(백업만 변경됨/양쪽 변경됨/이력 없이 내용 다름)나
  `DELETE-CANDIDATE`(원본에서 삭제됨)는 **절대 자동으로 덮어쓰거나 지우지 않음** — 리포트만
  하고 넘어간다.
- 실행 결과(stdout)의 `요약:` 줄을 그대로 파싱해 반환 형식 5번째 줄에 반영한다.
- `conflict` 또는 `delete_candidate`가 1건 이상이면, 해당 파일 경로와 이유를 사용자에게
  같이 보여준다(수동 확인 필요 — 세션 종료를 막지는 않음).
- 스크립트 실행 자체가 실패(예: PyYAML 없음, manifest 못 찾음)하면 "⚠️ lab 백업 실패:
  <이유>"로 보고하고, 이 단계 실패가 다른 단계 완료 여부에 영향을 주지 않는다 — 각 단계는
  서로 독립적으로 성공/실패를 보고한다.

## 반환 형식

5개 항목 각각 처리 결과를 체크리스트로 요약:
```
✅ Dev Notes 업로드: [YYYY-MM-DD] 제목 (링크)
✅/⏭️ lessons.md: 교훈 1건 추가 / 교훈 없음 — 생략
✅ todo.md: 완료 N건 이동, 신규 후속 M건 추가
✅ 데일리 노트: YYYY-MM-DD 갱신 (링크)
✅/⚠️ lab 백업: 변경 N개, 동일 N개, 제외 N개, 충돌 N개
```

## 공통 규칙

- 날짜는 항상 KST(UTC+9) 기준.
- 5개 단계는 서로 독립적이므로 순서 상관없이 처리 가능하지만, 위 순서(Dev Notes → lessons →
  todo → 데일리 노트 → lab 백업)를 기본으로 따른다.
- 실제로 일어난 일만 기록한다 — 애매하거나 확인 안 된 내용을 추측해서 채우지 않는다.
- Notion MCP 미연결 시: "/mcp 에서 notion 연결 상태를 확인하세요" 안내. Notion 단계(1, 4)가
  실패해도 lessons/todo/lab 백업(2, 3, 5)은 계속 진행한다 — 서로 독립.
